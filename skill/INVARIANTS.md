# INVARIANTS.md — simulink-toolbox 修改约束

> 目的：防止本 skill 在后续修改中偏离原始设计方向。
>
> 本文件不是理念说明，而是修改约束。任何改动都应先对照本文件判断是否偏移。
>
> 若改动违反任一"必须/禁止"项，默认拒绝；确有必要例外时，必须在改动说明中逐条解释。

---

## 1. 核心目标（仅作为判定总方向）

本 skill 的存在目的只有以下四条：

1. AI 识别 Simulink 任务后，应自然切到 MCP 工具路径，而不是回到普通 `.m`/Bash 老路
2. AI 制定计划时，应直接围绕 MCP 工具组合方案，而不是先写抽象计划、再零散补工具
3. 整体使用体验应保持低摩擦：操作少、认知负担低、维护成本低
4. 测试与兜底应尽量前置自动化，而不是把核查责任留给用户

注意：
"更规范 / 更完整 / 更可扩展 / 更通用"这类理由，只有在能明确服务于上述四条之一时才成立；否则不构成有效改动理由。

---

## 2. 核心规则（修改时必须满足）

**R1**（MCP 主路径）：禁止降级 MCP 或默认走普通脚本路径 → P3；`run_script`/`run_script_async` 是逃生舱，优先用具名 MCP 工具，见 map.md execute 分组决策规则  
**R2**（MCP 为构件）：计划需映射到具体 MCP 工具，不停留抽象描述 → P4  
**R3**（无仪式治理）：禁止用 audit/checklist 代替直接做好 MCP → P1  
**R4**（无摩擦增长）：禁止新增前置阅读/步骤/维护点 → P2  
**R5**（前置自动化）：新规则需评估 hook 检测，不靠用户发现 → P5

---

## 3. 架构约束

**核心层**（SKILL.md, map.md, 轻量 hook）必须精简可直接工作  
**扩展层**（patterns/*.md）禁止升格为"任务前必读"  
**注入**必须轻量：只做识别/提醒/指向，禁止大段 additionalContext  
**拦截**只防错误路径，禁止拦截合法 MCP 调用

---

## 4. 禁止漂移模式

**P1**（仪式治理）：禁止用 audit/checklist 代替直接做好 MCP (R3)  
**P2**（文档膨胀）：禁止不断加前置说明导致主路径膨胀 (R4)  
**P3**（导航补缺陷）：本该在 MCP 层修的能力问题不能硬补 (R1)  
**P4**（抽象计划）：计划需以 MCP 为实际构件，不只是说明 (R2)  
**P5**（用户兜底）：系统需自动防住问题，不靠用户发现 (R5)
